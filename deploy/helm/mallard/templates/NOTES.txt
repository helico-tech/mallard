mallard is installed as {{ include "mallard.fullname" . }} in namespace {{ .Release.Namespace }}.
Catalog: {{ .Values.catalog.type }}{{ if eq .Values.catalog.type "duckdb" }} (one pod, PVC {{ include "mallard.pvcName" . }}){{ end }}
Data:    {{ .Values.storage.dataPath }}
Public URL: {{ .Values.publicUrl }}

1. Wait until the pod is ready:

   kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "mallard.fullname" . }}

2. Reach it through the ingress ({{ .Values.publicUrl }}) or a port-forward:

   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "mallard.fullname" . }} 8080:{{ .Values.service.port }} 4318:{{ .Values.service.otlpHttpPort }} 4317:{{ .Values.service.otlpGrpcPort }}
   export MALLARD_URL=http://localhost:8080

3. Read the API token:
{{- if .Values.existingSecret }}
   export MALLARD_TOKEN=$(kubectl -n {{ .Release.Namespace }} get secret {{ .Values.existingSecret }} -o jsonpath='{.data.{{ .Values.existingSecretKey }}}' | base64 -d | cut -d, -f1)
{{- else }}
   export MALLARD_TOKEN=$(kubectl -n {{ .Release.Namespace }} get secret {{ include "mallard.fullname" . }} -o jsonpath='{.data.api-token}' | base64 -d | cut -d, -f1)
{{- end }}

4. Errors: create a Sentry project; the answer holds the DSN for your SDK:

   curl -s -XPOST "$MALLARD_URL/sentry/v1/projects" \
     -H "Authorization: Bearer $MALLARD_TOKEN" -H 'content-type: application/json' -d '{"name":"web"}'

5. Traces, logs, metrics: point OpenTelemetry SDKs at
   OTEL_EXPORTER_OTLP_ENDPOINT=http://{{ include "mallard.fullname" . }}.{{ .Release.Namespace }}:{{ .Values.service.otlpHttpPort }}   (OTLP/HTTP)
   or {{ include "mallard.fullname" . }}.{{ .Release.Namespace }}:{{ .Values.service.otlpGrpcPort }}   (OTLP/gRPC)

6. Look at it:  mallard status   |   mallard trace <trace-id>   |   mallard tui
   API docs: $MALLARD_URL/sentry/docs and $MALLARD_URL/otel/docs

NOTE: replicaCount={{ .Values.replicaCount }}. All pods take ingest and API requests. A status

{{- end }}
